# wgc

*Read this in [English](README.md).*

Minecraft Java 版のワールドから、プレイヤーが一度も近づいていないチャンクを削除します。

wgc は Anvil 形式（`.mca`）のワールドを対象にした、チャンクのガベージコレクタです。
`InhabitedTime` が 0 のチャンクを、そのチャンクのエンティティと POI のデータと一緒に削除し、結果を新しいフォルダに書き出します。
元のワールドは書き換えません。出力を `wgc verify` で確認してから、手動で入れ替えてください。

- 削除するのは `InhabitedTime = 0` のチャンクだけです。wgc が判断できないものは残します。
- 残すチャンクは元のバイト列のまま書きます。チャンクのデータを再エンコードすることはありません。
- 出力は元のワールドと突き合わせて検証し、通った場合だけ完了とします。

## インストール

各 [GitHub Release](https://github.com/panyaaa256/wgc/releases) で、ビルド済みのバイナリ（`wgc-<target triple>.tar.gz`）を配布しています。
Rust のツールチェーンがあれば、Cargo で直接インストールすることもできます。

```sh
cargo install --git https://github.com/panyaaa256/wgc --locked
```

インストールされるバイナリの名前は `wgc` です。
wgc は git の crate に依存しているので、crates.io には公開していません。

## 使い方

```sh
# 何も書き込まずにワールドを診断する
wgc scan ./world

# 削除される量を見積もる（--out がなければ何も書かない）
wgc gc ./world

# 結果を、存在しないフォルダか空のフォルダに書き出す
wgc gc ./world -o ./world-gc

# 出力を入れ替えてよいかを確かめる
wgc verify ./world-gc
```

バニラのサーバーとシングルプレイのワールドでは、ワールドフォルダを指定します。
Spigot や Paper などの Bukkit 系のサーバーでは、サーバーのルートフォルダを指定します。
指定を間違えているように見える場合は、wgc が警告を出します。

`wgc gc --out` を実行する前に、サーバーかゲームを止めてください。
wgc はワールドの `session.lock` をロックし、ワールドが使用中なら実行しません。

### 結果の入れ替え

`gc --out` が完了したときと `verify` が成功したときに、wgc が次の手順を実際のパスで表示します。

1. ゲーム（サーバー）を止める。
2. `wgc verify <out>` が成功することを確かめる。
3. `<path>` の名前を `<path>.wgc-bak` に変える。
4. `<out>` を `<path>` に移す。
5. ゲーム（サーバー）を起動して、ワールドを確かめる。
6. 問題がなければ `<path>.wgc-bak` を削除する。削除すると元に戻せないので、しばらく残しておくことを勧めます。
7. `<path>/.wgc/` は削除してかまいません。

Bukkit 系のサーバーでは、3 と 4 をワールドフォルダごとに行い、`.wgc/` は移しません。

### オプション

| オプション | コマンド | 意味 |
|---|---|---|
| `-o`, `--out <dir>` | `gc` | 結果を書き出す。なければ見積もりだけを表示する |
| `--dimension <id>` | `gc` | そのディメンションのチャンクだけを削除する（複数指定できる）。別名は `--dim`。`overworld`、`the_nether`、`the_end` には `minecraft:` を補う |
| `-f`, `--force[=<ids>]` | `gc` | 信用の確認で止まっても続行する。`--force` だけならすべて、`--force=T-3,T-5` なら指定した ID だけを無視する |
| `--source <path>` | `verify` | 元のワールドとして想定するパス。記録されたワールドと違えば、元のワールドの不一致で失敗する |
| `--json` | `scan`、`gc`、`verify` | 標準出力に JSON を出す。人向けの要約は標準エラーに出す |
| `--strict` | `scan`、`gc` | 警告があれば終了コード 1 で終わる |
| `-q`, `--quiet` | すべて | 進捗と要約を出さない。警告とエラーは出す |
| `-v`, `--verbose` | `scan`、`gc` | 要約に一覧（不合格になった対象、整合性の問題、出力しないファイル、古い地形との境界）を出す。`--quiet` とは同時に指定できない |
| `--no-color` | すべて | 色を使わない。環境変数 `NO_COLOR` にも従う |

詳しくは `wgc <command> --help` を見てください。

### 出力

- 人向けの要約は標準出力に出す。`--json` のときは標準エラーに出す。警告とエラーは常に標準エラーに出す。
- 進捗は、標準エラーが端末で、`--quiet` がないときだけ標準エラーに出す。
- 色は端末でだけ使う。`NO_COLOR` が空でない値に設定されているとき、`TERM` が `dumb` のとき、`--no-color` があるときは使わない。
- JSON の形は [`docs/json.md`](docs/json.md)（英語）にあります。

## 削除されるチャンク

`InhabitedTime` が 0 で、次のどれにも当てはまらないチャンクだけを削除します。

- 強制読み込みのチャンク、またはそこから 2 チャンク以内にある。
- 残すチャンクが、このチャンクから始まる構造物を参照している。
- リージョンファイルが壊れている。壊れたリージョンファイルは内容を変えずにコピーする。
- `--dimension` で対象から外したディメンションにある。

`InhabitedTime` がない、負の値である、または読めないチャンクは残します。

`gc` は、ゲームが必要としないファイルも出力しません。
対象は、サイズが 0 のリージョンファイル、プレイヤーデータの一時ファイル、チャンクがもう存在しない entities と poi のデータです。

## 信用の確認

上の規則は、「プレイヤーが近くにいれば `InhabitedTime` が増える」ことを前提にしています。
`gc --out` は書き出す前にこの前提を確かめ、成り立たないおそれがあれば止まります。

| ID | 止まる条件 |
|---|---|
| T-1 | Paper の `fixed-chunk-inhabited-time` が設定されていて、値が固定されている |
| T-2 | Paper 1.21.5 以降で、モブのスポーンが無効になっている。この場合 `InhabitedTime` が増えない（[PaperMC/Paper#12827](https://github.com/PaperMC/Paper/issues/12827)） |
| T-3 | `InhabitedTime = 0` のチャンクにプレイヤーがいる |
| T-4 | wgc が知っているものより新しいバージョンでワールドが保存されている |
| T-5 | 強制読み込みチャンクの情報を読めない |
| L-1 | ワールドに `session.lock` がない |

自分のワールドには当てはまらないとわかっている場合は、`--force`（または `--force=<ids>`）で続行できます。
ワールドが使用中のとき、出力先が不正なとき、空き容量が足りないとき、検証に失敗したときは、`--force` を付けても続行しません。

## 注意

- 事前生成したチャンクも削除します。事前生成したワールドでは、事前生成をやり直すことになります。
- 削除したチャンクは、次に読み込まれたときに、その時点のバージョンとワールド生成の設定で生成し直されます。古いチャンクとの境目で、地形がつながらないことがあります。
- ゴミ箱はありません。元のワールドを削除すると、元に戻せません。

## 終了コード

| コード | 意味 |
|---|---|
| 0 | 成功（警告があった場合と、`--force` で続行した場合も含む） |
| 1 | `--strict` を指定していて、警告があった |
| 2 | 引数の誤り |
| 3 | 何も書かずに止まった |
| 4 | エラー |
| 5 | 検証に失敗した |
| 130 | 中断された（Ctrl-C） |

- **3**: ワールドが使用中、または `session.lock` を書き込みで開けない。出力先が空でない、不正、またはワールドと重なる。確認で停止した。空き容量が足りない。
- **4**: ワールドの構成を認識できない、または読み書きに失敗した。
- **5**: 出力の検証に失敗した。または `verify` で、出力が不完全、別のワールドの記録、ワールドの変更で古くなった、ワールドが使用中のどれかだった。
- **130**: 処理中の段階が止まるのを待ち、`complete.json` は書かない。2回目の Ctrl-C ですぐに終わる。`gc --out` がすでに終わっていた場合は成功として扱う。

## 対応

- Anvil 形式の Minecraft Java 版のワールド。26.3（DataVersion 5023）まで
- バニラと Bukkit 系のサーバーの構成。26.1 で変わったファイルの配置にも対応する
