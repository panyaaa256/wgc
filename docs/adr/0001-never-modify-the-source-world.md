# ADR-0001: Never modify the source world

- Status: Accepted
- Date: 2026-11-09

## Context

Recorded retroactively from the original specification.

wgc deletes chunks from a Minecraft world. A bug in the deletion rule,
a crash halfway through a rewrite, or a world the game is still using
would destroy data that cannot be regenerated: player builds,
inventories, and terrain generated by older versions. Any tool that
rewrites region files in place has to get every one of these cases
right, every time.

## Decision

- wgc opens the source world read-only. The only exception is taking
  the `session.lock` lock ([0005](0005-lock-session-lock-like-the-game.md)),
  which neither creates the file nor changes its content.
- `wgc gc --out <dir>` writes the result to a path that does not exist
  yet or to an empty folder. The output may not lie inside the source
  world or contain it.
- The user swaps the output in manually (stop the server, run
  `wgc verify`, rename the original, move the output into place). wgc
  prints the steps with the real paths.
- wgc keeps no trash or backup of deleted chunks. The untouched
  original world is the restore path.
- There is no in-place mode in the MVP.

## Consequences

- A failed or interrupted run cannot damage the world; at worst it
  leaves an incomplete output folder
  ([0004](0004-mark-output-complete-only-after-verification.md)).
- The output is verified against the original, which is only possible
  because the original still exists.
- Costs: the output needs free disk space for a full copy of the kept
  data (wgc refuses to start when the estimate does not fit), and the
  copy takes time. Hard links cannot be used to save space
  ([0006](0006-never-hard-link-output-files.md)).
- Swapping is a manual step the user can get wrong; `wgc verify` exists
  to catch the dangerous cases (game started, files changed).
- Deferred: automatic swapping (`wgc swap`), an in-place mode, and
  reflink copies.
