# 出力の書き出しと検証（P7）

> 前提:
> - [plan.md](plan.md) の「Plan のモデル」
> - [region-format.md](region-format.md) の「書き込み（詰め直し）」
> - [world-layout.md](world-layout.md) の「ディメンションマップ」（`world_folders`、`server_root`）
> - 信用の確認の判定の使い方は [trust.md](trust.md) の「判定の使い方」（その節だけ）
>
> 実装先: `wgc-core` の `output` モジュール。

## 原則

- **元のワールドには決して書き込まない。** 元のワールドのファイルは、読み取り専用で開く。例外は `session.lock` のロックのための書き込み可能なオープンだけで、その中身も書き換えない。
- 出力先は新しいフォルダ。途中で止まっても、元のワールドには影響がない。
- 出力は、書き終えた後に元のワールドと突き合わせて検証し、通った場合だけ完了マーカーを書く。

## 実行の順序（`gc --out`、`clean --out`）

| 順 | 段階 | 失敗したとき |
|---|---|---|
| 1 | 出力先の確認（下の「出力先」） | 中止。何も書かない |
| 2 | すべてのワールドフォルダの `session.lock` をロックする | 中止。何も書かない |
| 3 | 元のワールドの状態を記録する（メモリ上。下の「元のワールドの状態」） | 中止。何も書かない |
| 4 | Plan を作る（[plan.md](plan.md)） | 中止。何も書かない |
| 5 | 信用の確認（`gc` のときだけ。[trust.md](trust.md)） | 中止。何も書かない |
| 6 | 空き容量の確認 | 中止。何も書かない |
| 7 | 出力を書く | `failure.json` を書いて終了 |
| 8 | 検証する | `failure.json` を書いて終了 |
| 9 | `source-state.json` と `complete.json` を書く | `failure.json` を書いて終了 |
| 10 | ロックを解放し、書き戻しの手順を表示する | — |

ロックは段階 2 から 9 まで保持する。段階 1〜6 で中止した場合は、出力先のフォルダを作らない。

## ロック

### 要件

- Minecraft（Java の `FileChannel.tryLock`）と**互いに排他になる** OS のロックを、`session.lock` にかける。
- ロックは待たずに試し、取れなければ中止する（「ワールドが使用中です。サーバー（ゲーム）を止めてから実行してください」）。
- ロックしている間に Minecraft を起動しようとすると、Minecraft はロックを取れずに起動しない。

### 実装の要件

- **Unix では `flock` を使わない。** Java は `fcntl` の POSIX ロックを使い、Linux では `flock` と `fcntl` のロックは互いに干渉しない。Rust の `File::try_lock`、`fs2`、`fs4` は `flock` なので使えない。
- Linux では OFD ロック（`fcntl(F_OFD_SETLK)`、ファイル全体、`F_WRLCK`）を使う。OFD ロックは POSIX ロックと競合する。OFD ロックがない Unix では `fcntl(F_SETLK)` を使う。
- **POSIX ロック（`F_SETLK`）は、同じプロセスで同じファイルの別のファイル記述子を閉じただけで解放される。** そのため、ロックしている間は、`session.lock` を他の目的で開かない（コピーも、検証での読み込みもしない。`stat` は開かないので使ってよい）。
- Windows では `LockFileEx`（`LOCKFILE_EXCLUSIVE_LOCK | LOCKFILE_FAIL_IMMEDIATELY`）を使う。
- `session.lock` は、読み書きで、作成せず、切り詰めずに開く。書き込み可能で開けない場合（権限）は中止し、サーバーと同じユーザーで実行するよう案内する。

### 例外

| 状況 | 扱い |
|---|---|
| `session.lock` がない | 確認 L-1（起動中かどうかを確認できない）。`--force` がなければ中止。指定されていれば、ロックなしで続行し、警告する。`clean --out` でも同じ |
| DataVersion が `DV_SESSION_LOCK_OS` より小さい | ロックは取るが、そのバージョンのゲームはロックを使わないので、起動中かどうかを検出できない旨を警告する |
| ネットワーク上の共有フォルダ | 別のマシンのプロセスとの間ではロックが確実には効かない。README に書く（検出はしない） |

## 出力先

- 出力先は、存在しないパスか、空のフォルダに限る。それ以外は中止する。
- 出力先が元のワールドの中にある、または元のワールドが出力先の中にある場合は、中止する（パスを正規化して比べる）。
- 出力先は、元のワールドと同じファイルシステムでなくてよい。

### 出力の構成

| レイアウト | 出力先の中身 |
|---|---|
| バニラ | 出力先 = ワールドフォルダ。元のワールドフォルダと同じ相対パスで書く |
| Bukkit | 出力先の直下に、各ワールドフォルダを同じ名前で置く（`<out>/<base>/`、`<out>/<base>_nether/` など）。サーバーのルートの他のファイル（jar、プラグイン、ログなど）は出力しない |

どちらの場合も、出力先の直下に、ツールの記録用のフォルダ `.wgc/` を作る。

## 空き容量

- 必要な容量 = Plan の見積もりの全体の出力サイズ × 1.01 + 64 MiB。
- 出力先（存在しなければ、存在する最も近い親）のファイルシステムの空き容量と比べ、足りなければ中止する。

## 書き出し

各ワールドフォルダの下を再帰的に辿り、すべてのファイルを次のように扱う。

| ファイル | 扱い |
|---|---|
| Plan にあるリージョンファイル | `FileAction` に従う。そのままコピー / 詰め直し（[region-format.md](region-format.md) の「書き込み」）/ 出力しない |
| Plan にある `.mcc` | Plan に従う。コピー / 出力しない |
| Plan の `omitted_other_files` にあるもの | 出力しない |
| `session.lock` | 出力しない（ゲームが起動時に作る。また、上の「実装の要件」の理由で開かない） |
| それ以外のすべてのファイル | そのままコピー |

- 空のディレクトリも作る。
- シンボリックリンクは、ゲームと同じく辿り、出力には実体を書く（ループは検出してエラーにする）。辿ったリンクは報告する。
- 通常のファイルとディレクトリ以外（FIFO など）は、出力せずに報告する。
- そのままコピーには、使えるなら reflink（コピーオンライト）を使い、使えなければ通常のコピーをする。**ハードリンクは使わない**（Minecraft はリージョンファイルをその場で上書きするので、元のワールドと出力の両方が書き換わる）。
- 各ファイルは書き終えたら fsync する。最後に、作ったすべてのディレクトリを fsync する（Unix）。

### メタデータ

- 権限のビットは、元のファイルからコピーする。
- 更新日時は、元のファイルの値にそろえる。
- 所有者: 実行ユーザーが root なら、元のファイルの所有者とグループに `chown` する。root でなく、元のファイルの所有者が実行ユーザーと違う場合は、「出力のファイルの所有者が実行ユーザーになる」旨を一度だけ警告する。
- Windows では、読み取り専用の属性だけをコピーする。

## 検証

出力を書き終えたら、元のワールドと突き合わせる。元のワールドはロックしているので、変わっていない。

| ID | 検証 |
|---|---|
| V-1 | 出力のすべてのリージョンファイルを解析し直し、構造エラーがない |
| V-2 | 出力の各リージョンファイルのエントリの集合が、Plan の残すエントリの集合（そのままコピーなら元のファイルの集合）と一致する |
| V-3 | 残す各エントリのペイロード（`4 + L` バイト）とタイムスタンプが、元のファイルのものと一致する。参照している `.mcc` の中身も一致する |
| V-4 | そのままコピーしたファイルの中身が、元のファイルと一致する（両方を読み直して比べる） |
| V-5 | 出力しないファイルが出力先になく、出力先に想定外のファイルがない（`.wgc/` を除く） |
| V-6 | 元のワールドの状態が、段階 3 で記録したものと一致する |

1つでも失敗したら、完了マーカーを書かず、失敗した項目をすべて `failure.json` に書く。

## 記録（`<out>/.wgc/`）

| ファイル | 書く時点 | 内容 |
|---|---|---|
| `source-state.json` | 段階 9 | 元のワールドの状態 |
| `complete.json` | 段階 9 の最後 | 完了マーカー |
| `failure.json` | 失敗したとき | 失敗の内容 |

### 元のワールドの状態（`source-state.json`）

```json
{
  "schema": "wgc.source-state/1",
  "source": "/abs/path/to/input",
  "layout": "bukkit_legacy",
  "world_folders": ["world", "world_nether", "world_the_end"],
  "files": [{ "path": "world/level.dat", "size": 1234, "mtime_ns": 0 }]
}
```

- 各ワールドフォルダの下のすべてのファイル（`session.lock` を含む。`stat` で得る）について、入力のパスからの相対パス、サイズ、更新日時（ナノ秒）を記録する。
- ゲームは起動時に `session.lock` を、保存のたびに `level.dat` を書き換えるので、`wgc verify` で起動の有無を検出できる。

### 完了マーカー（`complete.json`）

```json
{
  "schema": "wgc.complete/1",
  "tool_version": "0.1.0",
  "finished_at": "2026-11-09T12:34:56Z",
  "mode": "gc",
  "source": "/abs/path/to/input",
  "summary": { "deleted_chunks": 0, "size_before": 0, "size_after": 0 },
  "forced": ["T-3"]
}
```

- `forced` は、`--force` で無視した確認の ID の一覧（T-1〜T-5、L-1）。無視したものがなければ空の配列。

- 他のすべてのファイルを書き、fsync し、検証が通った後に書く。書いた後に fsync し、`.wgc/` も fsync する。
- **`complete.json` のない出力は、不完全な出力として扱う。** ユーザーには削除するよう案内する。

### 失敗の内容（`failure.json`）

```json
{
  "schema": "wgc.failure/1",
  "tool_version": "0.1.0",
  "stage": "verify",
  "error": "…",
  "items": [{ "check": "V-3", "path": "…", "detail": "…" }]
}
```

- `stage` は `write`、`verify`、`record`、`interrupted` のどれか。
- 失敗した出力は消さずに残す（不具合の調査と改善に使う）。不具合の報告に、この `failure.json` を添付するよう案内する。
- Ctrl-C で中断されたときも、できる範囲で `stage: "interrupted"` で書く。書けなくても、`complete.json` がないことで不完全だと分かる。

## `wgc verify <path> <out>`

書き戻してよいかを確かめる。読み取りだけを行う。

1. `<out>/.wgc/complete.json` がなければ、失敗「出力が完了していません」。
2. `<out>/.wgc/source-state.json` を読む。記録された `source` と `<path>`（正規化したもの）が違えば、失敗。
3. `<path>` の各ワールドフォルダの下のファイルを `stat` し、記録と比べる。追加、削除、サイズか更新日時の変更があれば、失敗。変わったファイルを一覧にする（「処理した後に、元のワールドが変更されています。書き戻すと、その間の変更が失われます」）。
4. `session.lock` のロックを試み、取れなければ失敗「ワールドが使用中です」。取れたらすぐに解放する。
5. すべて通れば、「書き戻せます」と表示し、書き戻しの手順を表示する。`complete.json` の `forced` が空でなければ、「`--force` で作った出力です（無視した確認: T-3 など）」と目立つように表示する（失敗にはしない）。

## 書き戻しの手順

`gc --out`／`clean --out` の完了時と、`wgc verify` の成功時に、実際のパスを埋めて表示する。

バニラ:

1. ゲーム（サーバー）を止める。
2. `wgc verify <path> <out>` を実行し、「書き戻せます」と表示されることを確かめる。
3. `<path>` を `<path>.wgc-bak` に名前を変える。
4. `<out>` を `<path>` に名前を変える（別のファイルシステムなら移動する）。
5. ゲームを起動して確かめる。
6. 問題がなければ `<path>.wgc-bak` を削除する。**ゴミ箱はないので、これを削除すると元に戻せない。** しばらく残しておくことを勧める。
7. `<path>/.wgc/` は削除してよい。

Bukkit: 手順 3 と 4 を、各ワールドフォルダ（`<root>/<base>`、`<root>/<base>_nether` など）について行う。`<out>/.wgc/` は書き戻さない。

補足として、該当する場合は次も表示する。

- 元のワールドにシンボリックリンクがあった場合: 出力では実体になっている。
- 所有者を引き継げなかった場合: サーバーを動かすユーザーが書き込めるか確かめる。

## 受け入れ条件

- 出力先が空でない、元のワールドの中にある、元のワールドを含む場合に、何も書かずに中止する。
- 別プロセスの Java（`FileChannel.tryLock`）が `session.lock` をロックしている間、ロックを取れずに中止する。逆に、ツールがロックしている間、Java はロックを取れない。Linux でこれを確かめる統合テストを用意する。
- ロックしている間に `session.lock` を開いて閉じる処理がない（テストで、処理の後もロックが保持されていることを確かめる）。
- GC した出力で、V-1〜V-6 がすべて通り、`complete.json` ができる。
- 書き出しの途中で失敗させると、`complete.json` がなく、`failure.json` がある。
- 出力のファイルの権限と更新日時が、元のファイルと一致する。
- `wgc verify` が、元のワールドの `level.dat` を書き換えた場合と、`session.lock` をロックしている場合に失敗する。
