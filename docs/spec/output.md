# 出力と検証（P7）

実装先: `core::output`。

元のワールドは読み取り専用で開く。例外は `session.lock` のロックのための書き込み可能なオープンだけで、中身は書き換えない。

## 実行の順序（`gc --out`）

| 順 | 段階 | 失敗したとき |
|---|---|---|
| 1 | 出力先の確認 | 中止（何も書かない） |
| 2 | 全ワールドフォルダの `session.lock` をロック | 中止 |
| 3 | 元のワールドの状態を記録（メモリ上） | 中止 |
| 4 | Plan を作る | 中止 |
| 5 | 信用の確認 | 中止（`--force` で続行） |
| 6 | 空き容量の確認 | 中止 |
| 7 | 出力を書く | `failure.json` を書いて終了 |
| 8 | 検証 | 同上 |
| 9 | `source-state.json`、`complete.json` を書く | 同上 |
| 10 | ロックを解放し、書き戻しの手順を表示 | — |

段階 1〜6 で中止したときは、出力先のフォルダを作らない。

## ロック

- Java の `FileChannel.tryLock` と排他になる OS のロックを、待たずに試す。取れなければ「ワールドが使用中です。サーバー（ゲーム）を止めてから実行してください」で中止する。
- Unix: `flock` は使わない（Linux では Java の `fcntl` ロックと干渉しない。`File::try_lock`、`fs2`、`fs4` も `flock`）。Linux は OFD ロック（`F_OFD_SETLK`、`F_WRLCK`、ファイル全体）、それ以外の Unix は `F_SETLK`。
- POSIX ロックは、同じプロセスで同じファイルの別の記述子を閉じると解放される。ロック中は `session.lock` を他の目的で開かない（`stat` はよい）。
- Windows: `LockFileEx`（`LOCKFILE_EXCLUSIVE_LOCK | LOCKFILE_FAIL_IMMEDIATELY`）。
- 読み書き・作成なし・切り詰めなしで開く。書き込みで開けなければ、サーバーと同じユーザーで実行するよう案内して中止する。

| 状況 | 扱い |
|---|---|
| `session.lock` がない | 確認 L-1。中止（`--force` でロックなしで続行し、警告） |
| DataVersion < `DV_SESSION_LOCK_OS` | ロックは取るが、起動中かどうかを検出できない旨を警告 |

## 出力先

- 存在しないパスか、空のフォルダに限る。元のワールドの中、または元のワールドを含むパスは不可（正規化して比べる）。
- バニラ: 出力先がワールドフォルダになる。Bukkit: 出力先の直下に各ワールドフォルダを同じ名前で置く（サーバーのルートの他のファイルは出力しない）。
- 出力先の直下に、記録用の `.wgc/` を作る。

## 空き容量

`全体の出力サイズ × 1.01 + 64 MiB` が、出力先（なければ最も近い親）の空き容量を超えたら中止する。

## 書き出し

各ワールドフォルダの下のすべてのファイル:

| ファイル | 扱い |
|---|---|
| Plan にあるリージョンファイル | `FileAction` に従う |
| Plan にある `.mcc` | Plan に従う |
| `omitted_other_files` | 出力しない |
| `session.lock` | 出力しない（ゲームが起動時に作る） |
| それ以外 | そのままコピー |

- 空のディレクトリも作る。
- シンボリックリンクは辿り、実体を書く（ループはエラー）。辿ったリンクは報告する。
- 通常のファイルとディレクトリ以外は出力せず、報告する。
- ハードリンクは使わない（Minecraft はリージョンファイルをその場で上書きするので、元のワールドも書き換わる）。
- 各ファイルを fsync し、最後に作ったディレクトリを fsync する（Unix）。
- 権限のビットと更新日時は元のファイルに合わせる。root で実行したら所有者とグループも合わせる。root でなく、所有者が実行ユーザーと違うときは、一度だけ警告する。Windows は読み取り専用の属性だけ。

## 検証

| ID | 検証 |
|---|---|
| V-1 | 詰め直したファイルに構造エラーがない |
| V-2 | 詰め直したファイルのエントリの集合が、Plan の残すエントリと一致する |
| V-3 | 詰め直したファイルの残すエントリのペイロードとタイムスタンプが、元と一致する |
| V-4 | そのままコピーしたファイル（`.mcc` を含む）のサイズが、元と一致する |
| V-5 | 出力しないファイルが出力先になく、想定外のファイルもない（`.wgc/` を除く） |
| V-6 | 元のワールドの状態が、段階 3 の記録と一致する |

失敗したら、すべての失敗を `failure.json` に書く。

## 記録（`<out>/.wgc/`）

### `source-state.json`

各ワールドフォルダの下の全ファイル（`session.lock` を含む）の、入力のパスからの相対パス、サイズ、更新日時（ナノ秒）。`stat` で得る。

```json
{
  "schema": "wgc.source-state/1",
  "source": "/abs/path/to/input",
  "layout": "bukkit_legacy",
  "world_folders": ["world", "world_nether", "world_the_end"],
  "files": [{ "path": "world/level.dat", "size": 1234, "mtime_ns": 0 }]
}
```

### `complete.json`

すべてを書いて fsync し、検証が通った後に書き、fsync する。これがない出力は不完全。

```json
{
  "schema": "wgc.complete/1",
  "tool_version": "0.1.0",
  "finished_at": "2026-11-09T12:34:56Z",
  "source": "/abs/path/to/input",
  "summary": { "deleted_chunks": 0, "size_before": 0, "size_after": 0 },
  "forced": ["T-3"]
}
```

`forced` は `--force` で無視した確認の ID（T-1〜T-5、L-1）。

### `failure.json`

```json
{
  "schema": "wgc.failure/1",
  "tool_version": "0.1.0",
  "stage": "verify",
  "error": "…",
  "items": [{ "check": "V-3", "path": "…", "detail": "…" }]
}
```

- `stage`: `write`、`verify`、`record`。
- 失敗した出力は消さずに残し、不具合の報告にこのファイルを添付するよう案内する。
- 中断されたときは何も書かない。

## `wgc verify <path> <out>`

読み取りのみ。

1. `complete.json` がなければ失敗（「出力が完了していません」）。
2. `source-state.json` の `source` が `<path>` と違えば失敗。
3. 各ワールドフォルダの下を `stat` し、記録と比べる。追加・削除・サイズか更新日時の変更があれば、変わったファイルを一覧にして失敗（「処理した後に、元のワールドが変更されています。書き戻すと、その間の変更が失われます」）。
4. `session.lock` のロックを試し、取れなければ失敗（「ワールドが使用中です」）。取れたらすぐ解放する。
5. 「書き戻せます」と表示し、書き戻しの手順を表示する。`forced` が空でなければ、「`--force` で作った出力です（無視した確認: …）」と目立つように表示する。

## 書き戻しの手順

`gc --out` の完了時と `wgc verify` の成功時に、実際のパスで表示する。

1. ゲーム（サーバー）を止める。
2. `wgc verify <path> <out>` で「書き戻せます」と出ることを確かめる。
3. `<path>` を `<path>.wgc-bak` に名前を変える。
4. `<out>` を `<path>` に移す。
5. 起動して確かめる。
6. 問題がなければ `<path>.wgc-bak` を削除する。削除すると元に戻せないので、しばらく残すことを勧める。
7. `<path>/.wgc/` は削除してよい。

Bukkit では、3 と 4 を各ワールドフォルダについて行い、`.wgc/` は移さない。シンボリックリンクを実体にした場合と、所有者を合わせられなかった場合は、その旨も表示する。

## 受け入れ条件

- 出力先が空でない、元のワールドの中、元のワールドを含む場合に、何も書かずに中止する。
- Java が `session.lock` をロックしている間は中止し、ツールがロックしている間は Java がロックを取れない（Linux の統合テスト）。処理の後もロックが保持されている。
- GC した出力で V-1〜V-6 が通り、`complete.json` ができる。
- 書き出しの途中で失敗させると、`complete.json` がなく `failure.json` がある。
- 出力の権限と更新日時が元と一致する。
- `wgc verify` が、`level.dat` を書き換えた場合と、`session.lock` がロックされている場合に失敗する。
