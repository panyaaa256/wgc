# 出力と検証

`gc --out` は、Plan（plan.md）に従って出力先に新しいワールドを書き出し、元のワールドと突き合わせて検証する。`wgc verify` は、その出力を書き戻してよいかを確かめる。

元のワールドは読み取り専用で開く。例外は `session.lock` のロック（lock.md）だけ。

## 実行の保証（`gc --out`）

- 出力先のフォルダを作る前に、次のすべてを確かめる。どれかで中止したときは、出力先のフォルダを作らない（何も書かない）。
  - 出力先の条件（「出力先」）
  - `session.lock` のロック（lock.md）
  - 信用の確認（T-1〜T-5、trust.md）と L-1
  - Plan を作れること
  - Plan に対する信用の確認
  - 空き容量（「空き容量」）
- `--force` で許されていない停止（T-1〜T-5、L-1）は、すべてのリージョンファイルを読み終える前にわかり、その時点で中止する。L-1 は信用の確認の結果とまとめて判定し、止まる ID をまとめて示す。`--force` で T-3 が許されているときは、T-3 は Plan に対してだけ確かめる。
- Plan に対する信用の確認でも、許されていない停止があれば中止する。この結果は、その間にファイルが変わらない限り、Plan を作る前の確認と同じになる（L-1 を無視してロックなしで続行した場合への備え）。
- `--force` で許された停止の警告（その確認を無視した旨、ロックなしで続行した旨）は、実際にその停止に当たって続行したときにだけ出す。
- 元のワールドの状態（「`source-state.json`」と同じ内容）は、Plan を作るために読む前に記録する（ロックを取れた場合は、ロックを保持した状態で）。V-6 はこの記録と比べる。
- ロックは、出力の書き出し、検証、記録が終わるまで保持し、その後に解放する。
- 書き出し、検証、記録のどこかで失敗したら、`failure.json` を書いて終了する。
- `complete.json` は、すべての出力を書き終え、検証が通り、`source-state.json` を書いた後にだけ置く。

### 中断

中断を求められたら、その場で止め、ロックを解放して「中断」で終わる。出力先は、`complete.json` も `failure.json` もないまま残る（不完全な出力）。

## 出力先

- 存在しないパスか、空のフォルダに限る。元のワールドの中、または元のワールドを含むパスは不可（存在する部分を正規化して比べる）。まだ存在しない部分に `..` を含むパスは不可。
- バニラ: 出力先がワールドフォルダになる。Bukkit: 出力先の直下に各ワールドフォルダを同じ名前で置く（サーバーのルートの他のファイルは出力しない）。
- 出力先の直下に、記録用の `.wgc/` を作る。

## 空き容量

`出力の合計サイズの見積もり（plan.md「見積もり」） × 1.01 + 64 MiB` が、出力先（なければ最も近い親）の空き容量を超えたら中止する。

## 書き出し

各ワールドフォルダの下のすべてのファイルを、次のように扱う。

| ファイル | 扱い |
|---|---|
| Plan にあるリージョンファイル | plan.md「ファイル」の扱いに従う |
| Plan にある `.mcc` | plan.md「ファイル」の `.mcc` の扱いに従う |
| Plan で出力しないリージョンファイル以外のファイル | 出力しない |
| `session.lock`（ワールドフォルダの直下） | 出力しない（ゲームが起動時に作る） |
| ワールドフォルダの直下の `.wgc/` | 出力しない（以前の実行の記録） |
| それ以外 | そのままコピー |

- 空のディレクトリも作る。
- シンボリックリンクは辿り、実体を書く。同じディレクトリに複数のリンクがあれば、それぞれのパスに書く。自分の祖先を指すリンク（ループ）はエラーにする。辿ったときは、シンボリックリンクを辿った旨を警告する。リンク先がないリンクは出力せず、特殊なファイルを飛ばした旨を警告する。
- 通常のファイルとディレクトリ以外は出力せず、特殊なファイルを飛ばした旨を警告する。
- ハードリンクは使わない（Minecraft はリージョンファイルをその場で上書きするので、元のワールドも書き換わる）。
- 出力するファイルの権限のビットと更新日時は、元のファイルに合わせる。root で実行したら、所有者とグループも合わせる（所有者を持たないファイルシステムでは、失敗にせず警告する）。root でなく、所有者が実行ユーザーと違うファイルがあれば、所有者を保てなかった旨を一度だけ警告する。Windows では読み取り専用の属性だけを合わせる。

### 永続性

`complete.json` を置く時点で、出力したすべてのファイル（内容とメタデータ）と作ったディレクトリは、ディスクに永続化されている。`complete.json` は完全な内容でだけ現れ（書きかけの `complete.json` は残らない）、置いた後はそれ自体も永続化されている。

## 検証

| ID | 検証 |
|---|---|
| V-1 | 詰め直したファイルに構造エラーがない |
| V-2 | 詰め直したファイルのエントリの集合が、Plan の残すエントリと一致する |
| V-3 | 詰め直したファイルの残すエントリのペイロードとタイムスタンプが、元と一致する |
| V-4 | そのままコピーしたファイル（`.mcc` を含む）のサイズが、元と一致する |
| V-5 | 出力先のファイルの集合が、Plan から独立に求めた「出力すべきファイル」の集合と一致する（`.wgc/` を除く） |
| V-6 | 元のワールドの状態が、Plan を作る前に記録した状態と一致する |

失敗は出力先のパスの順に並べる。失敗したら、すべての失敗を `failure.json` に書く。

## 記録（`<out>/.wgc/`）

形は docs/json.md が定める。

- `source-state.json`: 各ワールドフォルダの下の全ファイル（`session.lock` を含む）の、相対パス、サイズ、更新日時（ナノ秒）。`stat` で得た値。V-6 と `wgc verify` が比べる。
- `complete.json`: 出力が完了したことを示す。置く条件は「実行の保証」と「永続性」のとおり。これがない出力、または `failure.json` がある出力は不完全。
- `failure.json`: 書き出し、検証、記録のどこで失敗したかと、検証の失敗の一覧。失敗した出力は消さずに残す（不具合の報告に添付してもらう）。

## `wgc verify`

読み取りのみ。`--source` で元のワールドを指定しなければ、`source-state.json` の `source` を使う。次の順に確かめ、最初に当たった失敗で終わる。

1. `complete.json` がない、または `failure.json` がある → 不完全
2. `--source` を指定していて、記録の `source` と（両方を正規化して）違う → 元のワールドの不一致
3. 各ワールドフォルダの下をいま `stat` した結果を `source-state.json` と比べ、ファイルの追加・削除、サイズか更新日時の変更がある → 変更あり（変わったファイルと、追加・削除・変更の別の一覧を伴う）
4. 各ワールドフォルダの `session.lock` がロックされている（扱いは lock.md「コマンドごとの扱い」の `verify`） → 使用中

すべて通れば成功とし、`complete.json` の `forced` を返す。

## 区別する失敗

### `gc --out`

| 失敗 | 意味 |
|---|---|
| 出力先が空でない | 出力先が存在し、空のフォルダでない |
| 出力先のパスが不正 | 出力先のまだ存在しない部分に `..` を含む |
| 出力先が元のワールドと重なる | 出力先が元のワールドの中にある、または元のワールドを含む |
| ロックの失敗 | lock.md の「使用中」「書き込めない」「このプロセスが保持中」「その他の I/O」。「ない（L-1）」はここではなく「停止」に入る |
| 停止 | 信用の確認か L-1 で止まった（`--force` で許されていない ID の一覧を伴う） |
| 空き容量の不足 | 必要な容量と空き容量を伴う |
| レイアウトのエラー | world-layout.md の失敗 |
| 計画の失敗 | plan.md「区別する失敗」の失敗 |
| 検証の失敗 | V-1〜V-6 のどれかが通らなかった（すべての失敗を伴う） |
| その他の I/O | 上記以外の読み書きの失敗 |
| 中断 | 中断を求められた |

### `wgc verify`

| 失敗 | 意味 |
|---|---|
| 不完全 | `complete.json` がない、または `failure.json` がある |
| 元のワールドの不一致 | 指定した元のワールドが記録と違う |
| 変更あり | 記録した後に元のワールドのファイルが変わった |
| 使用中 | `session.lock` がロックされている |
| その他の I/O | 記録や元のワールドを読めない |

## 書き戻しの手順

`gc --out` の完了時と `wgc verify` の成功時に、CLI が実際のパスで表示する。

1. ゲーム（サーバー）を止める。
2. `wgc verify <out>` が成功することを確かめる。
3. `<path>` を `<path>.wgc-bak` に名前を変える。
4. `<out>` を `<path>` に移す。
5. 起動して確かめる。
6. 問題がなければ `<path>.wgc-bak` を削除する。削除すると元に戻せないので、しばらく残すことを勧める。
7. `<path>/.wgc/` は削除してよい。

Bukkit では、3 と 4 を各ワールドフォルダについて行い、`.wgc/` は移さない。シンボリックリンクを実体にした場合と、所有者を合わせられなかった場合は、その旨も表示する。

## 受け入れ条件

- 出力先が空でない、元のワールドの中、元のワールドを含む場合に、何も書かずに中止する。
- GC した出力で V-1〜V-6 が通り、`complete.json` ができる。
- 書き出しの途中で失敗させると、`complete.json` がなく `failure.json` がある。
- 中断を求めると「中断」で終わり、ロックが解放され、`complete.json` がない。
- 出力の権限と更新日時が元と一致する。
- `wgc verify` が、`level.dat` を書き換えた場合と、`session.lock` がロックされている場合に失敗する。
