# 計画

ワールドを読み、何を消してどう出力するかを決め、1つの Plan にまとめる。Plan を作る間、ファイルには書き込まない。

- `scan`、見積もり、`gc --out` は同じ規則で Plan を作る。`gc --out` は、実行時に Plan を改めて作る。
- 同じ入力からは、並び順も含めて同じ Plan ができる。
- GC の規則と clean の規則を常に両方適用する。`--dimension` があれば、GC の削除はそのディメンションだけで行う（clean の規則は全ディメンション）。

## リージョン三つ組の扱い

- 三つ組の3ファイルのどれかに構造エラー（region-format「エラーの区分」）があれば、その三つ組は **そのままコピー** にする。見つかった構造エラーはすべて記録する。
- region の各チャンクを展開して読む。展開か NBT の読み込みに失敗したチャンクは、内容エラーとして記録する。
- そのままコピーの三つ組でも、読めるチャンクは読み、構造物の参照を集める（下の R に使う）。

## 削除するチャンク

次の集合で決める。

1. 削除候補 C: GC の対象のディメンションの、そのままコピーでない三つ組にある、InhabitedTime が 0 のチャンク。
2. 強制読み込みによる保護 F: 各強制読み込みチャンクと、そこからチェビシェフ距離 2 以内のチャンク。
3. 構造物の参照による保護 R: 削除候補でないチャンク（InhabitedTime が正の値、タグなし、負の値、読めない、そのままコピーの三つ組にある、GC の対象外）と、F で残すチャンクが参照する構造物の開始点の和集合。参照は三つ組をまたぐ。参照は1回だけたどる（R で残したチャンクの参照はたどらない）。
4. 削除するチャンク D = C − F − R。

強制読み込みチャンクを確認できないディメンションは、Plan に記録する。`gc --out` ではこれが T-5 になり、`scan` と見積もりでは F なしで計算する。

## 判定

### InhabitedTime

| 区分 | 条件 |
|---|---|
| 値 | 0 以上の値 |
| タグなし | タグがない、または型が違う |
| 負の値 | 負の値。判断できないものとして扱う |
| 読めない | 展開か NBT の読み込みに失敗した（内容エラー） |

削除候補になるのは「値」が 0 のものだけ。

### region のチャンク

D に入るものだけ削除する。残すものには、次の優先順位で理由を1つ記録する（複数に当てはまれば、優先の数字が小さいもの）。

| 優先 | 残す理由 |
|---|---|
| 1 | そのままコピーの三つ組にある |
| 2 | `--dimension` の対象外 |
| 3 | 内容エラー（InhabitedTime が「読めない」） |
| 4 | InhabitedTime を判断できない（「タグなし」「負の値」） |
| 5 | InhabitedTime が正の値 |
| 6 | 強制読み込みによる保護（F） |
| 7 | 構造物の参照による保護（R） |

### entities／poi のエントリ

そのままコピーの三つ組では、すべて残す。それ以外は、同じ位置の region のチャンクで決める。

| region の同じ位置 | エントリの扱い |
|---|---|
| 残す | 残す |
| 削除する | 削除する（GC で削除したチャンク） |
| チャンクがない（ファイルがない、サイズ 0、エントリが空） | 削除する（本体のないエントリ。orphan） |

region が読めない場合は、三つ組がそのままコピーになっている。読めないことを「チャンクがない」とは扱わない。

### ファイル

三つ組の各ファイルの扱いは、次の条件を上から順に見て決める。

| 条件（上から順に） | 扱い |
|---|---|
| サイズ 0 | 出力しない |
| そのままコピーの三つ組 | そのままコピー |
| 削除するエントリがない | そのままコピー |
| 残すエントリがない | 出力しない |
| それ以外 | 残すエントリだけで詰め直す |

`.mcc` は、削除するエントリが参照しているものだけ出力せず、それ以外はコピーする。リージョンファイルのない `.mcc` は三つ組に属さないので、他のファイルと同じくそのままコピーする。

### リージョンファイル以外

プレイヤーデータの場所にある一時ファイル（`^[0-9a-f-]{36}-\d+\.dat$`）は出力しない。それ以外はすべてそのままコピーする（出力の対象の列挙は output.md「書き出し」）。

### 報告のみ

次のものは数えて報告するだけで、判定には使わない。

- 古い形式のチャンクの数: region のチャンクのうち、チャンクの DataVersion が `level.dat` の DataVersion より小さいもの。削除するかどうかに関わらず数える。
- 本体の `<uuid>.dat` がない `<uuid>.dat_old`。

## Plan の内容

Plan は、次のことを決めて持つ。`scan`、信用の確認（trust.md）、出力（output.md）は、これだけを材料にする。

- ワールドの構成と、GC の対象のディメンション（指定がなければ全ディメンション）
- 各三つ組の構造エラーと、そのままコピーにするかどうか
- region の各チャンクの、位置、InhabitedTime の区分、DataVersion、`blending_data` の有無、削除するか残すか（残すならその理由）
- entities／poi の各エントリの扱い、三つ組の各ファイルと `.mcc` の扱い（上の表から導く）
- 出力しないリージョンファイル以外のファイルと、その理由
- 強制読み込みチャンクを確認できないディメンション
- 本体のない `.dat_old`
- 見積もりと、古い地形との境界

並び順: ディメンションは ID の昇順、三つ組は座標の昇順、チャンクとエントリはインデックスの昇順、出力しないリージョンファイル以外のファイルはパスの昇順。

## 見積もり

ディメンション・種別ごとに、現在のサイズ（`.mcc` を含む）と出力後のサイズを出す。出力後のサイズは、そのままコピーなら現在のサイズ、詰め直すなら `8192 + Σ ceil((4 + L) / 4096) × 4096`（Σ は残すエントリについての和、`L` はエントリの長さ）、出力しないなら 0 に、コピーする `.mcc` のサイズを加えたもの。

リージョンファイル以外でそのままコピーするファイルの合計サイズも出す。出力の合計サイズ（output.md「空き容量」の確認に使う）には、これも含める。

## 古い地形との境界

D と上下左右で隣接する、残すチャンクのうち `blending_data` を持つもの（chunk-nbt.md）を集め、8 近傍で連結したまとまりごとに、チャンク数と範囲（最小と最大のチャンクの位置）を出す。

## 区別する失敗

壊れたファイルや壊れたチャンクは失敗にせず、Plan の中で扱う（そのままコピー、内容エラー）。

| 失敗 | 意味 |
|---|---|
| 読み込みの失敗 | OS がファイルを開かせない・読ませない（権限など）。判断の材料がないので中止する |
| レイアウトのエラー | ファイルの列挙に失敗した（同じ座標に2つの名前があるなど。world-layout.md） |
| 中断 | 中断を求められた |

## 受け入れ条件

- InhabitedTime が 0 のチャンクだけが削除され、タグなし、型の違い、負の値、内容エラーは残る。
- 強制読み込みチャンクの外側 2 チャンクまで保護され、3 チャンク目は保護されない。
- InhabitedTime が 0 でないチャンクから参照された開始点は、三つ組をまたいでも保護される。0 のチャンクからの参照では保護されない。
- 構造エラーのある三つ組では何も削除されない。
- region にチャンクがないエントリは本体のないエントリとして削除され、region が読めない場合は削除されない。
- サイズ 0 のファイルとプレイヤーデータの一時ファイルが出力されない。
- `--dimension` の対象外では、clean の規則だけが適用される。
- 同じ入力から2回作った Plan が等しい。
- 中断を求めると「中断」で終わる。
