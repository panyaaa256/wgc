# 診断

`scan` の内容は、`--dimension` なしの計画と信用の確認の結果だけから決まる。独自の判定はしない。`gc` の見積もりと結果も、同じ項目を報告する。

## 使用中のワールド

読み始める前に、ワールドのすべての `session.lock` のロックを試し（lock.md）、取れたら読み終わるまで保持する。取れなければ、取れなかった旨を警告して続行する。

## 項目

### 全体

- レイアウト（種類、`<base>`、ワールドフォルダ）
- `level.dat` の DataVersion
- ロックの状態
- 信用の確認の全項目
- 出力しない他のファイル（プレイヤーデータの一時ファイル）、本体のない `.dat_old`
- 固定の注意文の ID

ロックの状態は、取れた、または lock.md の失敗（使用中とこのプロセスが保持中は区別しない）のどれか。

### ディメンションごと

- 種別ごとのサイズ（`.mcc` を含む）
- region のチャンク数と、古い形式のチャンク数
- InhabitedTime の分布（下表）
- GC の見積もり: 削除するチャンク数、保護したチャンク数（`forceload`、`structure_ref`）、種別ごとの出力後のサイズ、残すエントリがなくなって出力しないファイル
- 整合性: 構造エラー（ファイル、ID、インデックス）、内容エラー（位置、種類）、そのままコピーの三つ組
- 本体のない entities／poi のエントリ（region の同じ位置にチャンクがないもの）の数（種別ごと）、サイズ 0 のファイル
- 古い地形との境界

### InhabitedTime の区分（tick）

| 区分 | 範囲 |
|---|---|
| `zero` | 0 |
| `missing` | タグなし、型の違い |
| `negative` | 負の値 |
| `unreadable` | 内容エラー |
| `lt_1s` | 1〜19 |
| `lt_10s` | 20〜199 |
| `lt_1m` | 200〜1199 |
| `lt_10m` | 1200〜11999 |
| `lt_1h` | 12000〜71999 |
| `lt_10h` | 72000〜719999 |
| `ge_10h` | 720000 以上 |

## JSON

`scan` は `wgc.scan/1`、`gc` は `wgc.gc/1` を出す。形は docs/json.md が定める。

## ターミナル出力

人向けの表示は標準出力に出す（`--json` のときは標準エラーに出し、`--quiet` なら出さない）。

1. レイアウト、DataVersion、ロック
2. 信用の確認（不合格と「確認できない」を目立たせ、`gc --out` で止まることと、`--force` で続行できることを出す。`session.lock` がない（ロックの状態が `missing`）ときは、止まる ID に L-1 も含める）。「確認できない」の理由は常に出す。不合格になった対象（ファイル、ワールドフォルダ、プレイヤーの位置）の一覧は `--verbose` のときだけ出す
3. ディメンションの表: サイズ、チャンク数、削除数、出力後のサイズ（「ディメンションの表」）
4. 合計: 現在、出力後、減る量
5. 整合性の問題の一覧（`--verbose` のときだけ）
6. clean の対象の一覧（`--verbose` のときだけ）
7. 古い形式のチャンクがあれば、公式の最適化を勧める
8. 古い地形との境界の一覧（`--verbose` のときだけ）
9. 固定の注意文

`gc` の見積もりでは、1〜6、8、9 を出す。各一覧は先頭 10 件までにし、残りは件数だけ出す。`--verbose` がないときに出さなかった一覧があれば、`--verbose` で見られることを出す。

### ディメンションの表

出力先が端末で、広い表がその幅に収まるときは広い表にし、そうでなければ狭い形にする。どちらも列の幅は中身に合わせる。

ディメンションの名前は `--dimension` に渡せる最も短い形で出す（`minecraft:overworld`、`minecraft:the_nether`、`minecraft:the_end` は名前空間を省き、他はそのまま）。JSON の `id` は省略しない。

- 広い表: 見出しの下と合計の行の上に、列の幅いっぱいの横線（`─`）を引く。3、4 の列に、整合性の問題の数、空ファイルの数、本体のない entities／poi のエントリの数、古い地形との境界の数を足す。合計の行は各列を足す。プレイヤーデータの一時ファイルはディメンションに属さないので、`--verbose` がなければ表の下に件数を出す。
- 狭い形: 3、4 だけを出す。`--verbose` がなければ、表の下に 5、6、8 の件数を1行にまとめて出す。

どちらも、件数が 0 の項目は出さない。

## 区別する失敗

| 失敗 | 意味 |
|---|---|
| UTF-8 でないパス | レポートに出すパスに UTF-8 でないものがある |
| 計画を作れない | 計画の作成が失敗した（plan.md の失敗） |

## 受け入れ条件

- InhabitedTime の各区分の境界値（-1、0、1、19、20、…、720000）が正しく分類される。
- JSON がスキーマに従い、同じ入力からバイト単位で同じ JSON ができる。
- 構造エラーのある三つ組が `integrity` に出る。
- ロックを取れない場合に警告して続行し、`lock` に状態が出る。
- UTF-8 でないパスがあると、レポートの作成がエラーになる。
