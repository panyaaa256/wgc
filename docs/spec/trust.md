# InhabitedTime の信用の確認（P5）

> 前提:
> - [world-layout.md](world-layout.md) の「level.dat」「プレイヤーデータ」「Paper の設定ファイル」「ディメンションマップ」
> - [plan.md](plan.md) の「Plan のモデル」（チャンクの InhabitedTime を引くため）
> - [versions.md](versions.md)
>
> 実装先: `wgc-core` の `trust` モジュール。

## 目的

GC の判定は「InhabitedTime が 0 なら、プレイヤーが半径 128 ブロック以内に来たことがない」という前提に立つ。この前提が崩れている環境では、プレイヤーが来たチャンクでも 0 のまま保存されるので、GC を実行してはならない。このフェーズでは、その前提を確かめる。

### 前提が崩れる環境

| 環境 | 内容 | 確認 |
|---|---|---|
| Paper 系で `fixed-chunk-inhabited-time` が 0 以上 | 全チャンクの InhabitedTime が固定値になる。既定値は `-1`（無効） | T-1 |
| Paper 1.21.5 以降で、モブのスポーンが無効 | Paper 固有の不具合で、InhabitedTime が加算されない（PaperMC/Paper#12827） | T-2 |
| mod や外部ツールで作成・編集されたワールド | 値が予測できない | T-3 で部分的に検出する |
| 上記に、過去の一時期だけ該当していた | ワールドのファイルだけでは完全には検出できない | T-3 で部分的に検出する。残りは README に書く |

### 参考: InhabitedTime の加算条件（バニラ）

毎 tick、次の条件を満たすチャンクに、経過 tick 数が加算される。

1. エンティティが処理される範囲にある。
2. 128 ブロック以内に、スペクテイター以外のプレイヤーがいる（carpet などの偽プレイヤーも含む）。
3. 加算はチャンクごとに 1 回で、近くのプレイヤー数には依存しない。

## 確認の一覧

| ID | 確認 | 対象 |
|---|---|---|
| T-1 | Paper の設定 | Bukkit のレイアウトのとき |
| T-2 | モブのスポーン | Bukkit のレイアウトで、DataVersion ≥ `DV_1_21_5` のとき |
| T-3 | プレイヤーの位置 | すべて |
| T-4 | バージョン | すべて |
| T-5 | 保護の情報 | すべて（`gc` のとき） |

## T-1: Paper の設定

各ワールドフォルダの `paper-world.yml` と、`<server_root>/config/paper-world-defaults.yml` を読む。YAML のライブラリを使う。

キー: `chunks` の下の `fixed-chunk-inhabited-time`。

| ワールドごとの値 | 判定 |
|---|---|
| 0 以上の整数 | 不合格 |
| `-1` | 合格 |
| `default`、キーがない、ファイルがない | 既定値のファイルの値で判定する |

| 既定値のファイルの値 | 判定 |
|---|---|
| 0 以上の整数 | 不合格 |
| `-1`、キーがない、ファイルがない | 合格 |

- YAML として読めない、値の型が想定外の場合は「確認できない」。
- 不合格のときは、どのファイルのどの値かを表示する。
- 設定を有効にしたのが最近なら、それより前に保存されたチャンクの値は本物である。そのため、他の確認と同じく `--force` で続行できる。

## T-2: モブのスポーン

各ワールドフォルダの `level.dat` のゲームルールで、モブのスポーンが無効になっていれば不合格。

- Bukkit 系では、ゲームルールはワールドごとにある。各ワールドフォルダの `level.dat` を読む。
- ゲームルールの形式（[world-layout.md](world-layout.md) の「level.dat」）を読めない、またはツールが知らないバージョンなら「確認できない」。
- バニラのレイアウトでは対象外（バニラでは、モブのスポーンの設定に関係なく加算される）。
- Spigot など、Paper 以外の Bukkit 系では不具合は起きないが、ファイルからは区別できない。その場合は `--force` で続行する。
- 要調査: PaperMC/Paper#12827 の修正状況。修正されたバージョンが分かれば、対象をそれより前に絞る。また、不具合の条件が厳密に「モブのスポーンが無効」なのか、「スポーンするカテゴリーが空」（`spawn-limits` がすべて 0 など）なのかも確認する。

## T-3: プレイヤーの位置

プレイヤーの最後の位置にあるチャンクの InhabitedTime が 0 なら、その値は信用できない（信用できるワールドでは、プレイヤーが 1 tick でもいたチャンクは 0 より大きくなる）。

### 対象

- プレイヤーデータの場所の `<uuid>.dat`（`.dat_old` と一時ファイルは除く）
- `level.dat` の `Data.Player`（あれば。シングルプレイヤーのワールド）

### 読むフィールド

| フィールド | 型 | 内容 |
|---|---|---|
| `Pos` | Double の List（3 要素） | x、y、z |
| `Dimension` | Int または String | Int なら `0` = `minecraft:overworld`、`-1` = `minecraft:the_nether`、`1` = `minecraft:the_end`。String ならそのまま ID。形式はタグの型で判断する |
| `playerGameType` | Int | `3` はスペクテイター |

### 判定

各プレイヤーについて:

1. スペクテイター（`playerGameType == 3`）なら飛ばす（加算の対象外のため）。
2. `Dimension` がディメンションマップにない、またはフィールドを読めない場合は飛ばし、報告する。
3. チャンクの位置 `(floor(x / 16), floor(z / 16))` を求める。
4. そのチャンクが存在しない場合は飛ばす（他のツールで削除された可能性がある）。InhabitedTime が「判断できない」場合も飛ばす。
5. InhabitedTime が 0 なら、そのプレイヤーを「該当」とする。

結果:

| 状況 | 判定 |
|---|---|
| 該当が 1 件以上 | 不合格。該当するプレイヤー（UUID、ディメンション、チャンクの位置）をすべて表示する |
| 該当がなく、確認できたプレイヤーが 1 人以上 | 合格 |
| 確認できたプレイヤーが 0 人（プレイヤーデータがない、すべて飛ばした） | 確認できない（例: 事前生成しただけで、誰も遊んでいないワールド） |

補足: 信用できない時期にログアウトしたまま来ていないプレイヤーがいれば、その位置で過去の時期も検出できる。

## T-4: バージョン

`level.dat` の DataVersion が `DV_MAX_KNOWN` より大きければ、「確認できない」（[versions.md](versions.md) の「ツールが知らないバージョン」）。

## T-5: 保護の情報

Plan の `protection_unknown` が空でなければ、「確認できない」。強制読み込みチャンクかスポーンの情報を読めず、保護を計算できないため。

## 結果のモデル

P6 と P8 はこのモデルだけを使う。

```rust
pub struct TrustReport {
    pub checks: Vec<CheckResult>,   // ID の順
}

pub struct CheckResult {
    pub id: CheckId,                // T1..T5
    pub status: CheckStatus,
}

pub enum CheckStatus {
    Pass,
    Fail { details: Vec<String> },  // 表示用の項目（ファイルと値、プレイヤーと位置など）
    Unknown { reason: String },
    NotApplicable,
}
```

## 判定の使い方

| コマンド | 扱い |
|---|---|
| `scan`、`gc`／`clean` の見積もり | すべての結果を表示する。中止しない |
| `gc --out` | 下の規則で中止する |
| `clean --out` | 確認しない（clean は InhabitedTime を使わない） |

`gc --out` の規則:

- 不合格か「確認できない」が 1 つでもあれば、中止する。中止するときは、出力先に何も書かない。
- `--force` が指定されていれば、中止せずに続行する。T-1〜T-5 のすべてが、`--force` で続行できる（元のワールドには書き込まないので、判定が誤っていても、間違った出力ができるだけで、元のワールドから取り戻せる）。
- `--force` で続行するときは、無視した確認（不合格と「確認できない」）を、すべて目立つように表示する。無視した確認の ID は、`complete.json` の `forced` に記録する（[output.md](output.md) の「完了マーカー」）。

`--force` で続行できない停止（ワールドの使用中、出力先の不正、空き容量の不足、検証の失敗、レイアウトの判定のエラー）は、[cli.md](cli.md) の「停止と `--force`」にまとめてある。

## 受け入れ条件

- T-1: ワールドごとの値 `0`、`-1`、`default`、キーなし、と、既定値のファイルの値の組み合わせで、表のとおりに判定される。
- T-2: Bukkit で DataVersion ≥ 4325 かつモブのスポーンが無効なら不合格、バニラなら対象外になる。
- T-3: スペクテイター、存在しないチャンク、マップにないディメンションが飛ばされる。0 のチャンクにいるプレイヤーが 1 人いれば不合格になる。プレイヤーが 0 人なら「確認できない」になる。
- T-3: `Dimension` が Int と String の両方の形式で読める。シングルプレイヤーの `Data.Player` も対象になる。
- `gc --out` で、不合格か「確認できない」があると中止し、`--force` があると続行する。続行したときは、無視した確認の ID が `forced` に記録される。
