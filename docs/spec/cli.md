# CLI（P8）

> 前提:
> - [scan.md](scan.md) の「ターミナル出力」
> - [output.md](output.md) の「書き戻しの手順」
> - 信用の確認の続行用のフラグは [trust.md](trust.md) の「判定の使い方」（その節だけ）
>
> 実装先: `wgc` クレート（`crates/cli`）。引数の解析は clap。`wgc-core` の関数を呼び、結果を整形して出力する。

## コマンド

```
wgc scan   <path> [--json <file>]
wgc gc     <path> [--out <dir>] [--dim <id>]... [--allow-zero-at-player] [--allow-mob-spawning-off] [--allow-unknown]
wgc clean  <path> [--out <dir>] [--allow-unknown]
wgc verify <path> <out>
```

`<path>` は、バニラではワールドフォルダ、Bukkit 系ではサーバーのルートフォルダ。

### `scan`

- 読み取りのみ。端末に要約を出す（[scan.md](scan.md) の「ターミナル出力」）。
- `--json <file>`: JSON を `<file>` に書く。`-` なら標準出力に書き、そのときは端末向けの要約を標準エラーに出す。

### `gc`

| 指定 | 動作 |
|---|---|
| `--out` なし | 見積もりを出すだけ。何も書かない |
| `--out <dir>` | `<dir>` に出力を書く（[output.md](output.md) の「実行の順序」） |

| オプション | 意味 |
|---|---|
| `--dim <id>` | GC の削除を、そのディメンションだけで行う。複数指定できる。`<id>` は `minecraft:the_nether` の形式か、省略形 `overworld`、`the_nether`、`the_end`（`minecraft:` を補う）。clean の規則は、指定に関係なく全ディメンションに適用する。存在しない ID はエラー |
| `--allow-zero-at-player` | 信用の確認 T-3 の不合格でも続行する |
| `--allow-mob-spawning-off` | 信用の確認 T-2 の不合格でも続行する |
| `--allow-unknown` | 「確認できない」項目があっても続行する。`session.lock` がない場合も続行する |

続行用のフラグを使った場合は、使ったフラグを実行時に表示し、`complete.json` の `overrides` に記録する。

### `clean`

`gc` から GC の規則を除いたもの。InhabitedTime を使わないので、信用の確認はしない。`--allow-unknown` は `session.lock` がない場合のためだけにある。

### `verify`

[output.md](output.md) の「`wgc verify`」のとおり。

## 終了コード

| コード | 意味 |
|---|---|
| 0 | 成功 |
| 1 | 成功したが、警告がある |
| 2 | 引数の誤り（clap の既定に合わせる） |
| 3 | 安全のための確認で中止した（使用中、信用の確認、出力先、空き容量）。何も書いていない |
| 4 | エラー（I/O、レイアウトの判定の失敗など） |
| 5 | 検証の失敗（`gc`／`clean` の出力の検証、`verify` での変更の検出や使用中の検出） |

`scan` と見積もりは、信用の確認が不合格でも中止しない。その場合の終了コードは 1。

## 固定の注意文

決まった場面で、毎回同じ文を出す。ID は JSON の `notices` で使う。

| ID | 出す場面 | 文 |
|---|---|---|
| `pregenerated_chunks` | `gc` の見積もりと実行、`scan` | 事前生成したチャンクも削除対象になります。事前生成したワールドでは、その効果がなくなります。 |
| `boundary_general` | 削除するチャンクがあるとき | 削除したチャンクは、次に読み込まれたときに、現在のバージョンとワールド生成の設定で再生成されます。古い地形との境目では、段差や途切れた地形が出ることがあります。 |
| `no_trash` | `gc --out`、`clean --out` の完了時 | 元のワールドは変更していません。書き戻した後も、確認できるまで元のワールドを残してください。ゴミ箱はないため、元のワールドを削除すると元に戻せません。 |
| `run_official_optimize` | 古い形式のチャンクがあるとき | 古い形式のチャンクが N 個あります。公式の「ワールドの最適化」（`--forceUpgrade`）を勧めます。 |

## 出力の方針

- 進捗は、端末のときだけ標準エラーに表示する（リージョン三つ組の処理数）。端末でないときは出さない。
- 警告とエラーは標準エラーに出す。
- 中止したときは、理由と、続行の方法（あれば、続行用のフラグ）を出す。
- メッセージの言語は未決（[../spec.md](../spec.md) の「未決事項」）。決まるまでは日本語で書き、メッセージを1か所にまとめておく。

## 受け入れ条件

- 各コマンドの `--help` が出る。
- `gc` を `--out` なしで実行すると、ファイルを何も書かない（テストで、ワールドの全ファイルの更新日時が変わらないことを確かめる）。
- 終了コードが、各状況で表のとおりになる。
- `--dim` の省略形と、存在しない ID のエラー。
- `scan --json -` で、標準出力が JSON だけになる。
